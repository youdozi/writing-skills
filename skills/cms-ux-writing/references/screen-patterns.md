# CMS 화면별 문구 선택

요청한 영역만 적용한다. 아래 상태를 모든 화면에 만들거나 구현을 바꾸라는 요구가 아니다.

## 편집·저장·게시

편집 화면에서는 제목·본문·슬러그·분류·공개 범위 등 실제 필드 이름을 사용한다. 슬러그 예시가 필요하면 제공된 URL 규칙 안에서 쓰고 주소 변경의 리디렉션·검색 영향·자동 생성 정책을 추측하지 않는다. 업로드 안내는 실제 허용 확장자·최대 크기·필수 여부에 맞추고 검증 실패를 업로드 완료로 표시하지 않는다.

저장 버튼, 저장 중 상태, 마지막 저장 시각, 저장 성공/실패는 서로 다른 용도다. 자동 저장은 지원 여부와 저장 위치가 주어져야 말할 수 있다. 브라우저에 남은 입력과 서버에 저장된 내용, 공개 사이트에 반영된 내용을 구별한다. 변경사항이 없다는 상태와 저장하지 않은 변경사항이 있다는 상태도 합치지 않는다.

게시 권한이 없는 작성자가 초안을 저장하거나 검토를 요청할 수 있다면 그 행동을 안내한다. 저장을 위해 게시 권한을 요청하라고 바꾸지 않는다. 게시 예약을 설정하는 문구는 예약 시각·시간대를 제공된 형식으로 전달하고 일정 등록을 게시 완료로 바꾸지 않는다. 원래 게시물이 공개된 채 수정 초안만 바뀌는 제품이라면 그 차이를 유지한다.

## 오류·변경 충돌

필수값 누락·형식 위반은 실제 필드와 해결할 입력을 지정한다. 서버 장애의 원인을 알 수 없으면 네트워크 단절·용량 초과·권한 문제 등으로 단정하지 않는다. ‘다시 시도’는 실제 재시도 동작이 있을 때 사용한다. 사용자가 할 수 없는 조치를 반복 요구하지 않는다.

다른 사용자가 먼저 저장한 충돌에서는 확인된 저장 상태와 덮어쓰기 영향을 구별한다. 현재 입력이 사라진다고 단정하거나 입력이 안전하게 보존된다고 약속하지 않는다. 비교·복사·새로고침·복구·강제 저장 중 실제 제공된 경로만 안내한다. 다른 사용자의 이름·문서 제목 등은 표시 권한과 제공 자료 범위를 따른다.

## 목록·검색·권한

처음 콘텐츠가 없는 상태에는 작성 권한이 있을 때 첫 작성 경로를 안내할 수 있다. 검색 결과가 없으면 필터 변경/초기화가 지원되는지에 맞춰 안내한다. 접근 제한이나 불러오기 실패를 ‘등록된 글이 없습니다’로 쓰지 않는다. 전체 개수와 조회 가능한 개수, 선택 개수의 단위를 구별한다.

비활성 버튼의 이유를 요청받으면 현재 역할에서 할 수 없는 행동을 짧게 설명한다. 접근 권한 요청·관리자 문의·역할 전환 등이 실제 지원되는 경우에만 다음 행동으로 쓴다. 보이지 않아야 할 리소스의 존재나 민감한 정보를 문구로 새로 노출하지 않는다.

## 삭제·일괄 작업

확인 대화상자는 제목·영향 설명·실행 버튼·취소 버튼이 같은 동작을 말하게 한다. 삭제 대상이 ‘선택한 글 3개’라면 ‘전체 글’로 늘리지 않는다. 휴지통 보관 기간·연결 파일 삭제·공개 중단 여부·복구 가능성은 제공된 정책에 맞추고, 알 수 없는 영향을 채우지 않는다. 실제로 가능한 더 명확한 행동명 ‘휴지통으로 이동’ 등을 사용할 수 있다.

일괄 처리 결과는 성공·실패·미확인·건너뜀을 제공된 결과에 맞춰 구별한다. 수량 합계가 선택 범위와 맞지 않으면 임의로 남은 항목의 결과를 만들어 합계를 맞추지 않는다. 재시도는 실패 항목만 다시 처리하는지, 전체를 다시 실행하는지에 맞춘다. 성공한 항목을 다시 처리해도 안전하다는 보장은 별도 근거가 필요하다.

## 문자열 파일 전달

키/원문/수정문/화면/표시 조건 표가 필요한 작업이면 요청한 열만 제공한다. 문자열 JSON은 입력 키와 변수 목록을 유지한다. `{count}`가 글 개수라는 명세가 있으면 파일 수로 바꾸지 않고, 중괄호 문법이 무엇인지 모르는 상태에서 임의 템플릿 형식으로 치환하지 않는다. 문장을 조각내 이어 붙이는 설계나 복수형 규칙을 새로 만들기보다 기존 렌더링 계약을 따른다.
