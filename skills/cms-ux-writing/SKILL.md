# CMS 화면 글쓰기

콘텐츠를 관리하는 사람이 지금 상태, 행동의 대상과 결과, 다음에 할 수 있는 일을 이해하도록 쓴다. 기본은 간결하고 차분한 한국어다. 브랜드를 홍보하는 말보다 작업을 구분하는 말을 우선한다. 숙련자만 쓰는 도구라고 가정하거나 불필요하게 유아적인 말투로 바꾸지 않는다.

## 화면과 동작 파악

새 문구·기존 문구 퇴고·화면별 문구 설계·문자열 검토 중 요청한 작업을 수행한다. 제공된 화면·명세·코드·기존 문구에서 대상, 현재 상태, 사용자 역할, 행동과 결과, 가능한 복구/다음 경로를 파악한다. 필요한 자료만 읽으며 문구 작업만으로 CMS에 접속하거나 실제 게시·삭제·권한 변경을 실행하지 않는다.

모든 조건을 질문하지 않는다. 화면의 목적과 동작이 충분하면 가능한 문구부터 쓴다. 복구 여부·공개 범위·저장 결과처럼 뜻을 바꾸는 정보가 없으면 결론을 발명하지 말고 해당 부분만 확인하거나, 요청한 자리표시자/별도 확인 메모로 구별한다. 단순 메뉴·버튼 수정에 전체 시스템 명세를 요구하지 않는다. 화면 시안용으로 가정한 상태의 문구는 작성할 수 있으나 실제 처리가 끝났다는 보고와 구별한다.

## 상태와 결과를 정확하게 쓰기

같은 제품의 용어와 상태 이름을 일관되게 쓴다. 상태가 다른데 단어를 통일한다며 하나로 합치지 않는다. 작업에 필요한 [화면별 패턴](references/screen-patterns.md)만 참고한다.

- 임시 저장·검토 요청·승인·게시·게시 예약·게시 중·공개 중단을 실제 동작에 맞춘다. 초안 저장을 방문자에게 공개됐다는 뜻으로 쓰지 않는다. 예약이 등록된 사실과 예정 시각에 실제 공개된 사실을 구별한다. 자동 저장·반영 범위·실행 취소가 제공되지 않았다면 약속하지 않는다.
- 완료 문구는 성공한 대상과 범위를 말한다. 요청이 접수됐거나 대기 중인데 완료로 쓰지 않는다. 일부만 성공한 일괄 작업은 성공·실패·결과 미확인을 구별하고 제공된 수량과 단위를 보존한다. 현재 페이지에서 선택한 항목과 검색 결과 전체 선택도 혼동하지 않는다.
- 서버 응답이 없다는 이유만으로 실패·롤백·미저장을 단정하지 않는다. 중복 실행 위험이 있는 게시·삭제·결제 등의 결과가 미확인이면 확인 가능한 상태 조회 경로를 먼저 안내하고, 실제 제공되지 않은 재시도·복구 기능을 만들지 않는다. 확정 실패에 대해 지원되는 재시도를 불필요하게 막지는 않는다.
- 삭제·덮어쓰기·공개 범위 변경 확인은 대상, 영향, 복구 가능 여부를 확인한 범위에서 전달한다. 휴지통 이동을 영구 삭제로, 영구 삭제를 언제든 복원 가능한 행동으로 쓰지 않는다. 확인창·추가 승인을 모든 행동에 일률적으로 요구하지 않는다. 운영상 동작을 카피로 새로 정하지 않는다.

## 라벨·오류·다음 행동

메뉴는 찾을 대상, 버튼은 수행할 행동을 예측하게 쓴다. ‘확인’·‘처리’만으로 다른 작업을 구별하지 않는다. 다만 문맥과 기존 용어가 충분한 짧은 문구를 불필요하게 늘리지 않는다. 취소·닫기·이전·나가기·변경사항 버리기는 실제 효과가 다르면 구별한다.

필드 라벨과 예시·도움말·검증 오류를 구별한다. 정해진 필수 여부·형식·범위·크기·허용 유형을 정확히 쓰고 자리표시자만으로 필드 이름을 대신하지 않는다. 오류는 무엇을 어떻게 수정하면 되는지 알려 주며 사용자를 탓하지 않는다. 시스템 장애·접근 권한 문제를 입력 오류로 안내하지 않는다. 입력값 보존·자동 복구·관리자 연락 경로는 실제로 지원될 때만 말한다.

처음 사용해 비어 있는 화면, 필터/검색 결과 없음, 권한이 없어 보이지 않는 상태, 로딩 중, 불러오기 실패를 구별한다. 데이터가 없다는 사실과 조회하지 못했다는 사실은 다르다. 권한 안내에는 현재 가능한 행동만 제시하고 존재하지 않는 권한 신청 버튼·연락처를 발명하지 않는다. 실제 역할을 근거 없이 ‘관리자’로 부르지 않는다.

기능 이름·대상·필요한 상태를 문구에 드러내고 ‘여기’·색·위치만으로 안내하지 않는다. 중요한 결과나 데이터 손실 안내에서 유머·능청·비꼼으로 의미를 흐리지 않는다. 문구 검토만으로 실제 화면의 접근성·포커스·보조기술 알림·반응형 배치를 검증했다고 하지 않는다.

## 기존 문구·구조화된 문자열

수정 범위, 보호 문구, 키, 변수·태그, 길이 제한과 반환 형식을 따른다. 말투 교정만으로 버튼 동작·권한·정책·수치·공개 상태를 바꾸지 않는다. 단위와 조건을 없애서 길이를 맞추지 않는다. 길이와 의미가 충돌하면 필요한 최소 조정을 짧게 알리거나 지정된 대안을 따른다.

문자열 키·자리표시자와 포맷은 제공된 계약을 보존한다. 변수 이름을 번역하거나 새로운 변수를 임의 추가하지 않는다. JSON 요청은 파싱 가능한 JSON으로 반환하고 JSON만 요청하면 코드펜스·해설을 붙이지 않는다. 복수형·날짜·시간대·상대시각은 제공된 렌더링 방식에 맞추며 지원되지 않은 ICU 등의 문법을 새로 넣지 않는다. 예약 시각의 시간대나 글자 수 계산 기준이 뜻을 바꾸면 그 기준을 확인한다.

다른 언어의 새 UI 문구는 대상 언어·지역·격식을 따르고, 언어만으로 사용자의 나이·성별·숙련도를 정하지 않는다. 완성 문자열의 번역·대조만 요청하면 사용 가능한 translate가 적합하며 키·변수·제품 동작은 번역 중에도 유지한다.

## 검토와 전달

문구만 먼저 읽어 대상·현재 상태·다음 행동을 구별할 수 있는지 확인한 뒤 원자료와 대조한다. 작업 상태, 실패 원인과 확실성, 삭제 영향, 수량·단위·일시·권한, 버튼과 실제 동작의 일치를 살핀다. 임의 정책·원인·복구 약속을 추가하지 않았는지 확인한다. 복잡한 작업이나 별도 리뷰 요청에서 위임이 허용되면 원래 요청·화면/명세·문구를 분리된 검토자에게 주고 최초 판정·수정·재확인을 구별한다. 선택적인 취향 제안을 동작 오류와 혼동하지 않는다.

기본 출력은 요청한 화면 문구다. 여러 상태를 설계하면 상태나 영역별로 위치를 구별하고, 문자열 파일·표·본문만 등 지정 형식을 따른다. 화면 설계 전체·검토표·장황한 작법 설명을 자동으로 덧붙이지 않는다. 미확인 동작을 사용자에게 보일 문구 속 임시 사실로 숨기지 않는다. 실제 CMS 수정·배포 여부는 카피 작성 결과와 별도로 보고한다.

방문자용 홈페이지·랜딩페이지 카피는 사용 가능한 website-copywriting, 게시할 글의 본문은 writing/tech-blog-writing이 적합하다. 다른 스킬이나 특정 CMS 제품·외부 연결은 이 스킬의 필수 의존성이 아니다.
