# 홈페이지 글쓰기

방문자가 무엇을 제공하는 곳인지 이해하고, 자신에게 맞는지 판단하고, 필요한 다음 행동을 선택할 수 있도록 쓴다. 자연스럽고 간결하게 쓰되 결정에 필요한 조건을 줄이지 않는다. 모든 페이지의 목적을 구매·가입으로 정하지 않는다.

## 요청과 자료 파악

기획·전체 초안·특정 영역 문구·퇴고 중 요청한 작업을 수행한다. 방문자, 제공하는 것, 페이지 목적, 다음 행동과 이동 대상, 사용할 사실과 브랜드 말투를 주어진 자료에서 파악한다. 업종·언어·연령만으로 독자의 성향을 단정하지 않는다.

빠진 항목을 모두 질문하지 않는다. 제품·서비스 자체나 작성 목적을 정할 수 없을 때만 핵심을 짧게 묻는다. 일부 가격·연락처 등이 없으면 그 주장을 생략하거나 필요한 편집 메모로 분리해 가능한 부분을 작성한다. 사용자가 자리표시자를 허용하면 무엇을 채워야 하는지 명확히 표시한다. 원고만 요청했다면 작업 메모와 임시 사실을 게시용 문구에 섞지 않는다.

실제 사업·제품의 기능, 가격, 세금·결제 주기, 제공 지역, 일정, 응답 시간, 자격, 성과와 정책은 제공 자료나 확인한 출처 범위에서 쓴다. 기능이 해결할 수 있는 일과 성과 보장을 구별한다. 없는 고객 후기·로고·고객 수·인증·수상·시장 순위·할인·무료 체험·재고·마감·보안 보장을 만들지 않는다. 가상 서비스의 시안 요청이면 가상임을 전달 맥락에서 구별하고, 실제 운영 사실이 되는 것은 아님을 지킨다. 법적 고지나 개인정보 처리 조건을 문구만으로 확정하지 않는다.

## 페이지 구성과 문장

전체 페이지는 방문자가 가진 질문과 판단 순서에 맞춰 필요한 영역만 고른다. 서비스 사이트는 대상·제공 가치·이용 방법·조건, 포트폴리오는 작업과 역할·의뢰 범위, 정보 사이트는 찾을 내용과 접근 경로가 중심이 될 수 있다. [영역별 선택](references/page-copy.md)은 해당 영역을 작성할 때만 참고한다. 모든 페이지를 같은 문제 제기·기능·후기·FAQ·문의 틀로 채우지 않는다.

- 첫 화면은 제목과 짧은 설명을 함께 읽었을 때 제공 대상과 쓰임을 알 수 있게 한다. 감성적인 브랜드 문장을 살릴 수 있지만 모호한 구호만으로 설명을 대신하지 않는다. 기능 목록을 되풀이하기보다 방문자가 할 일과 연결한다.
- 소제목은 해당 영역의 내용을 예측하게 쓴다. 같은 장점을 제목·설명·카드·결말에서 표현만 바꿔 반복하지 않는다. 짧은 단락·목록·표는 정보 관계에 따라 고른다. 화면 너비를 확인하지 않았다면 줄 수·모바일 적합성을 검증했다고 하지 않는다.
- 주요 행동은 페이지 목적에 맞게 두고 보조 행동과 구별한다. 버튼·링크 문구는 이동할 내용이나 수행할 행동과 맞춘다. 문의 폼으로 가는데 ‘예약 확정’, 영업 상담인데 ‘바로 시작’, 유료 조건이 있는데 무조건 ‘무료’라고 쓰지 않는다. 실제 URL이 없으면 경로를 발명하지 않고 문구와 의도한 이동 대상을 구별해 전달한다. 문구만 요청하면 경로 표를 강제하지 않는다.
- 말투는 일관되게 유지한다. 과장된 불안·가짜 긴박감·독자 면박으로 행동을 유도하지 않는다. 가벼운 위트는 이해를 돕는 범위에서 쓰며 요금·오류·동의 조건의 의미를 흐리지 않는다. 접근 가능한 글을 위해 제목과 링크의 의미를 명확히 쓰되, 카피 검토만으로 웹 접근성 준수를 인증하지 않는다.

## 퇴고와 다른 언어

지정한 영역·길이·보호 문구를 따른다. 자연스럽게 다듬는 요청만으로 사업 범위·가격·조건·보장·버튼 동작을 바꾸지 않는다. 여러 페이지를 함께 쓰면 서비스명·요금·용어·문의 경로가 서로 맞는지 확인하되 한 영역의 최소 수정까지 전체 재설계로 확대하지 않는다.

요청 언어와 지역·격식에 맞게 쓴다. 새 외국어 카피와 완성 원문의 번역을 구별하며 금액·단위·지역·정책을 현지화 명목으로 임의 변경하지 않는다. 언어별 고정 글자 수나 SEO 공식으로 판단하지 않는다. 완성 원문의 번역·대조만 요청하면 사용 가능한 translate가 적합하고, 없어도 이 스킬을 실행하는 데 필수 의존성은 없다.

검색용 제목·설명을 요청하면 본문과 같은 제공 범위를 정확하게 요약한다. 키워드를 억지로 반복하거나 모든 페이지에 같은 설명을 붙이지 않는다. 고정 길이를 노출 보장 기준으로 제시하거나 검색 순위·검색결과 문구·전환율을 보장하지 않는다. 구체적인 검색엔진 동작·규정·변경 정보를 주장할 때는 최신 공식 자료를 확인한다.

## 검토와 전달

원고만 먼저 읽어 제공 내용·대상·다음 행동이 이해되는지 확인하고, 자료와 대조해 수치·조건·증거와 버튼의 약속을 점검한다. 페이지 문구만으로 구매율·사용성을 실측했다고 하지 않는다. 별도 검토를 요청받았거나 복잡한 원고에서 위임이 허용되면 원래 요청·자료·원고를 분리된 검토자에게 주고 최초 판정과 수정본을 구별한다. 실제 오류와 선택적인 취향 제안은 나눈다.

기본 출력은 요청한 영역별 완성 문구다. 전체 페이지라면 영역 이름으로 위치를 알아볼 수 있게 제시하고, 기획을 요청한 경우에만 방문자 질문·영역 역할·문구의 관계를 설명한다. A/B 후보·기획표·검토표·제목 후보·SEO 문구를 자동으로 덧붙이지 않는다. 게시를 막는 핵심 미확인 사항은 숨기지 말고 원고 밖에 짧게 밝히거나 필요한 확인을 받는다.

마케팅·PR 목적의 광고·캠페인 이메일·SNS·보도자료·언론 대응 원고는 사용 가능한 marketing-pr-writing이 적합하다. CMS·관리자 화면의 편집·게시·권한·오류 안내는 사용 가능한 cms-ux-writing이 적합하다. 코드·시각 디자인·게시까지 요청받으면 사용 가능한 제작 도구나 사이트 스킬로 구현을 이어갈 수 있지만 문구 작성만으로 구현·배포한 것으로 처리하지 않는다. 이 스킬 자체는 특정 제작 도구·외부 서비스 연결을 요구하지 않는다. 블로그 해설은 writing/tech-blog-writing, 영상 대본은 screenplay-writing이 사용 가능하면 해당 작업에 더 적합하다.
