# 시나리오 창작

읽는 사람이 장면을 보고 듣고, 인물의 선택과 변화가 어떻게 이어지는지 따라갈 수 있는 시나리오를 만든다. 사용자가 정한 매체·장르·말투·언어·형식·분량과 기존 설정을 우선한다.

## 요청과 결과물 선택

기획, 구성, 대본, 이어쓰기, 각색, 퇴고·리뷰 중 요청한 작업을 수행한다. 로그라인 요청을 완성 대본으로, 완성 장면 요청을 줄거리 설명으로 바꾸지 않는다. 새 글의 기본 언어는 한국어이고, 기존 작품은 언어와 목소리를 보존한다. 매체가 미정이면 영화·드라마용으로 읽기 쉬운 영상 대본을 기본값으로 삼는다. 특정 플랫폼·공모전의 제출 규격을 충족한다고 주장하지 않는다.

자유 창작의 빈자리는 합리적으로 채우되 실제 자료·고정 설정과 구별한다. 핵심 설정이 충돌해 다음 행동의 의미를 결정할 수 없을 때만 필요한 사실을 짧게 확인한다. 사용자가 이미 답한 내용을 다시 묻지 않는다. 충실한 각색에서는 원작의 사건·동기·결말을 임의로 확정하거나 바꾸지 않는다.

작업에 해당하는 지침만 읽는다.

| 작업 | 읽을 지침 |
| --- | --- |
| 로그라인·시놉시스·트리트먼트·씬 구성 | [이야기 설계](references/story-design.md) |
| 장면·대본 작성, 각색, 행동·대사 퇴고 | [장면과 대본](references/screenplay.md) |
| 이어쓰기, 연속성, 장편·회차 관리, 리뷰 | [연속성과 검토](references/continuity-review.md) |

이 스킬의 결과물은 영상 시나리오·대본이다. 실제 영상 파일의 제작은 별도 작업이며, 대본 출력만으로 영상 제작이 끝났다고 하지 않는다.

소설 산문은 사용 가능한 `writing`, 완성된 글의 번역만 요청하면 사용 가능한 `translate`가 담당한다. 다른 스킬이 없어도 요청 범위에서 직접 처리하며 전환했다고 주장하지 않는다. 소프트웨어 테스트·운영 시나리오에는 이 작법 지침을 적용하지 않는다.

## 공통 창작 기준

- 인물의 장면 목표, 걸림돌, 행동·대응과 그 결과를 연결한다. 회상·서정·실험적 형식에 갈등·반전·교훈을 강요하지 않는다.
- 관객이 아는 정보와 각 인물이 아는 정보를 구별한다. 인물이 알 수 없는 사실로 행동하게 만들지 말고, 정보가 전달되는 시점과 수단을 설계한다.
- 성격은 구체적인 선택과 반응으로 드러낸다. 말투는 상대·상황·관계에 따라 달라질 수 있으며 모든 인물을 같은 주제 해설자로 만들지 않는다.
- 간결함은 불필요한 설명·반복·이동을 줄이는 기준이다. 긴장과 감정을 만드는 호흡·침묵·반복을 살리고, 물리적으로 가능한 행동과 인과관계를 지우지 않는다.
- 출연 인원·장소·소품·효과·대사 금지 등 제작 조건을 지킨다. 화면 밖 목소리나 문자 속 새 인물로 인원 제한을 우회하지 않는다. 필요한 제작 가정은 짧게 밝힌다.
- 러닝타임은 추정치다. 글자·장면·페이지 수만으로 정확한 재생 시간을 보장하지 않는다. 엄격한 시간 제한이 있으면 추정 근거와 실측하지 않은 범위를 구분한다.

## 전달

기본 출력은 요청한 결과물 자체다. 요청하지 않은 작법 강의·제목 후보·검토표·계획 설명을 붙이지 않는다. 리뷰만 요청하면 문제의 근거와 수정 방향을 제시하고 전체를 임의로 다시 쓰지 않는다. 전달 전 요청 조건과 설정·연속성을 대조한다.

검토는 AI를 우선한다. 별도 검토 요청이나 복잡한 대본에서 위임이 허용되고 별도 AI 맥락이 사용 가능하면 [독립 검토](references/continuity-review.md)를 적용한다. 그렇지 않으면 자체 검토이며 독립 검토라고 하지 않는다. 파일 저장은 요청·저장소 관례를 따르고, 창작 요청만으로 외부 게시·투고·메시지 전송을 수행하지 않는다.
