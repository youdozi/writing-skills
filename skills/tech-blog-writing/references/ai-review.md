# 독립 AI 검토

완성 초안·장문 번역·다국어 동기화를 AI로 검토할 때 사용한다. 별도 세션 또는 검토 에이전트가 사용 가능하고 위임이 허용된 경우 적용한다. 도구가 없다면 두 관점의 자체 검토를 하되 별도 세션 검토로 기록하지 않는다. 사람의 검토는 선택 사항이다.

## 입력과 독립성

작성 과정의 대화 이력을 전달하지 않는 새 검토 맥락에 다음만 제공한다.

- 검토 대상 글과 원문 또는 사실 자료.
- 대상 독자·언어·문체·용어집·요청 범위.
- 적용할 스킬과 필요한 참고 지침.

이전 통과 판정·예상 정답·발견할 오류 목록을 최초 검토 입력에 넣지 않는다. 번역 검토자가 기존 자체 평가 보고서를 읽지 않도록 대상 파일을 명시한다. 검토자는 우선 읽기 전용으로 의견을 내며, 수정은 작성자가 원문과 근거를 대조해 수행한다.

동일 모델이라도 작성 맥락과 분리된 세션에서 검토할 수 있다. 이를 다른 모델의 합의나 사람·원어민의 검토로 표현하지 않는다. 세션 분리는 오류나 편향이 제거됐다는 보장이 아니다.

## 검토 순서

1. 대상 언어의 글만 읽어 독자의 질문에 답하는지, 핵심 답이 일찍 드러나는지, 흐름·용어·지시 대상·문체·제목·표·캡션·출력 설명이 명확한지 확인한다. 반복·불필요한 배경·예제·형식적 결론을 줄일 수 있는지 살피고, 짧은 글에 소제목·표·해설을 과도하게 붙이지 않았는지 확인한다. 명시한 상세 설명·단계·분량 요청을 과도하게 압축하지 않는다. 명사화·긴 수식·우회 표현, 주어와 서술어의 호응, 모호한 지시어와 불필요한 접속어를 확인한다. 표현을 줄이면서 가능성·격식·저자의 말투가 달라지지 않았는지도 대조한다.
2. 원문·자료와 대조해 누락·추가·부정·조건·불확실성·수치의 대상과 구간·코드·출처·판단 시점·조치 상태를 확인한다. 개발 환경과 운영 결과, 유의차 미확인과 효과 부재도 구분한다. 압축한 글은 삭제 전후의 결론·적용 범위·실행 가능성이 같은지 확인한다. 정보를 재배치하면서 적용 환경·조건이 빠지거나 접속어가 원자료에 없는 시간 순서·인과를 더하지 않았는지 대조한다. 의미를 보존한 뒤에는 문장별 정보량과 연결을 살펴, 한 문장에 예외와 미확인 사항이 몰려 다시 읽어야 하는 부담을 줄인다.
3. 위치, 최소한의 문제 인용, 심각도, 이유, 수정안, 확신도를 제시한다. 실제로 실행하거나 조회한 항목과 정적 검토만 한 항목을 나눈다.

## 판정과 수정

| 구분 | 기준 | 처리 |
| --- | --- | --- |
| 중대 | 핵심 주장·부정·수치·코드·보장 범위를 잘못 전달 | 해결 전에는 해당 범위를 검토 통과로 표시하지 않음 |
| 주요 | 조건 누락·용어 충돌 등으로 독자가 다르게 해석할 가능성이 큼 | 원문과 대조해 수정하거나 쟁점을 명시 |
| 경미 | 의미를 유지하는 명료성·문체 개선 | 저자의 의도와 효과를 보고 선택 |

여러 AI의 의견이 다르면 다수결로 결정하지 않는다. 해당 원문·코드·지표 정의와 대조해 채택 또는 보류 이유를 기록한다. 검토자가 제시한 수정안도 새로운 사실이나 원문에 없는 확신을 더하는지 확인한다.

보통 최초 검토 1회와 채택한 수정의 재확인 1회로 마무리한다. 새 중대 문제가 발견되거나 수정 범위가 달라진 경우에만 추가 검토한다. 반복해도 해결되지 않는 쟁점은 범위와 불확실성을 기록하고 통과한 것처럼 처리하지 않는다. 자동으로 사람의 승인을 요청하지 않는다.

## 최소 검토 기록

평가·별도 리뷰를 요청받았거나 중요한 문제를 수정한 경우 다음을 남긴다. 일반 글 결과물마다 긴 검토표를 붙이지 않는다.

- 작성·검토 세션의 구분, 대상 파일 버전 또는 해시, 독자·언어·검토 범위.
- 지적 사항과 심각도, 채택·보류한 이유, 수정 내용.
- 재확인 결과, 실행한 검사와 남은 불확실성.

최초 검토는 이전 결론 없이 수행하고, 수정 재확인에는 최초 지적과 변경분을 제공해도 된다. '검토 범위에서 해결되지 않은 중대 문제를 발견하지 못함'을 모든 언어와 주제의 정확성 보장으로 확대하지 않는다.
