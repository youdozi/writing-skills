# 추가 언어의 작성·교정

중국어 간체·스페인어·독일어 요청에서 해당 언어 절만 읽는다. 사용자 문체·지역·용어집이 우선한다. 아래 교정 기준은 언어 전체의 독자 성향을 추정하는 규칙이 아니다. 평가 사례의 통과를 모든 주제·지역·장문의 품질 인증으로 확대하지 않는다.

## 중국어 간체

- 간체와 번체를 구별하고 요청한 표기를 유지한다. 공식 이름·식별자까지 일괄 문자 변환하지 않는다. 기술 용어는 프로젝트 표기를 우선하며 `缓存`과 다른 지역의 대응어를 이유 없이 섞지 않는다.
- 중국어 산문에는 자연스러운 중국어 구두점을 사용하되 코드·경로·서식 토큰의 ASCII 기호는 보존한다. 긴 수식어와 `的` 연결은 주체·조건을 흐리는 경우에만 나눈다.
- `最多重试两次`와 최초 포함 총 실행 횟수를 구별하고, `不必`와 `不得`처럼 의무 없음과 금지를 대조한다. 병렬 문장을 줄여도 각 조건의 대상은 남긴다.

## 스페인어

- 지역을 지정하지 않았다면 특정 지역의 속어·독자상을 추정하지 않는다. 원문·프로젝트의 `tú`/`usted` 및 설명체를 유지하고 성·수 일치, 악센트와 대명사의 지시 대상을 확인한다.
- 기술 용어는 첫 등장에 필요한 만큼 설명하며 `reintento`, `solicitud`, `caché` 등 선택한 표기를 일관되게 쓴다. 모든 영어 용어를 병기하거나 공식 API 이름을 번역하지 않는다.
- `no es necesario`와 `no se permite`, 최대 재시도 횟수와 총 시도 횟수를 구별한다. 소수·천 단위 표기를 바꾸더라도 값과 수량의 대상을 대조하며 코드·로그는 보존한다.

## 독일어

- 원문·프로젝트의 `du`/`Sie`와 설명체를 일관되게 유지한다. 언어만으로 독일·오스트리아·스위스 지역이나 독자 수준을 지정하지 않는다.
- 명사의 대문자, 격·성·수와 대명사의 지시 대상을 점검한다. 긴 합성어나 명사 중심 표현이 관계를 흐리면 동사 중심으로 풀되 기술 용어와 공식 식별자는 남긴다. 문장 길이 자체를 고정 제한하지 않는다.
- `nicht alle`와 `keine`, `muss`와 `kann`의 범위를 확인한다. `Wiederholungsversuche`가 최초 실행을 포함하는지 원문과 대조한다. 소수·천 단위 기호를 조정해도 값과 단위는 보존하며 코드·로그에는 산문 표기를 적용하지 않는다.
