# 일반 글쓰기

독자와 장르에 맞는 글을 쓴다. 간결함은 불필요한 반복을 줄이는 기준이며, 장면·감정·목소리나 요청한 분량을 없애는 이유가 아니다.

## 팩트 기반·픽션 기반 선택

글의 기반과 장르는 따로 정한다. 일상·커뮤니티·해설도 요청에 따라 실제 자료를 쓰거나 가상 상황을 다룰 수 있다. 사용자가 지정한 기반을 우선하고, 두 버전 비교를 원하면 같은 주제로 각각 작성한다.

- **팩트 기반:** 확인한 자료와 사용자가 제공한 실제 경험·기록 안에서 쓴다. 제공 메모와 외부 검증 사실, 관찰과 해석·추정을 구별한다. 없는 사건·대화·감각·속마음·수치·인용·출처를 흥미나 분량을 위해 채우지 않는다. 비유·문학적 표현·유머는 사실 관계와 감정의 강도를 지키며 사용할 수 있다. 개인 경험마다 외부 출처를 요구하지 않고, 검증이 필요한 주장은 관련 조사 지침으로 확인한다.
- **픽션 기반:** 요청과 정해진 설정 안에서 인물·사건·대화·내면·장면을 창작한다. 화자의 시점, 시간·공간, 인물이 아는 정보와 이야기의 인과를 일관되게 유지한다. 허구를 실제 체험·취재·발언의 증거로 제시하지 않는다. 실제 역사·과학 등을 사실로 설명하는 부분은 별도로 확인한다.

기반이 미지정이면 목적·자료·기존 원고로 판단한다. 실제 사건·정보 해설·체험 기록은 팩트 기반, 명시적인 소설·가상 장면 창작은 픽션 기반으로 처리한다. 퇴고는 원문의 기반을 유지하며, ‘소설처럼’ 등 문체 변경만으로 실제 경험에 새 사건을 보태지 않는다. 허구 각색을 허용하면 고정할 사실·설정과 창작할 부분의 범위를 따른다. 요청과 자료로 창작 허용 여부를 결정할 수 없고 그것이 결과를 바꾸는 경우에만 짧게 확인한다.

두 기반을 함께 쓰는 글은 실제 부분과 가상 예시·재구성의 경계를 독자가 알아볼 수 있게 한다. 가상 사례가 실제 증거로 오인될 수 있는 지점에 짧게 표시하고, 제목·장르로 허구임이 이미 분명하면 그 맥락을 활용한다. 사실 해설 속 가상 예시는 실제 관측·검사 결과로 바꾸지 않는다.

## 작업 선택

요청이 기획·개요·초안·이어쓰기·퇴고 중 무엇인지 판단하고 그 결과물을 제공한다. 독자·게시 장소·말투·분량·제공 자료를 따른다. 부족한 정보는 합리적인 기본값으로 처리하되 핵심 사건이나 주제 자체가 없어 진행할 수 없을 때만 묻는다. 다만 실제 경험 기반 일상 글에서 자료량과 최소 분량이 충돌하거나 원문 속 사실이 서로 맞지 않으면 [일상 지침](references/everyday.md)에 따라 필요한 확인이나 지정된 대안을 처리한다. 새 글의 기본 언어는 한국어이고 기존 글은 언어와 저자의 목소리를 유지한다. 다른 언어도 요청에 따라 쓰되 평가한 언어의 범위를 넘어 품질이 검증됐다고 하지 않는다.

작업에 해당하는 지침만 읽는다. 혼합 장르는 주된 독자 목적을 중심으로 필요한 절을 함께 적용한다. 프랑스어로 작성·퇴고할 때는 [프랑스어 문장 교정](references/french-editing.md)도 적용한다. 러시아어 초안의 문법 교정·별도 문장 검토에는 [최소 문법 교정](references/russian-proofreading.md)을 적용한다.

| 글의 목적 | 읽을 지침 |
| --- | --- |
| 개념·현상·작품을 이해시키거나 근거를 들어 평가하기 | [교양 해설·비평](references/explanatory.md) |
| 개발 프로젝트 고객에게 요구사항·일정·비용·변경·장애·검수 내용을 전달하고 협의하기 | [고객 커뮤니케이션](references/client-communication.md) |
| 사건을 이해시키거나 쟁점에 대한 의견을 전하기 | [시사](references/current-affairs.md) |
| 질문·경험·정보를 공유하고 대화하기 | [커뮤니티](references/community.md) |
| 실제 생활의 순간·생각·감정을 기록하기 | [일상](references/everyday.md) |
| 허구의 인물·장면·사건을 만들거나 이어가기 | [소설](references/fiction.md) |

사실 기반 해설·비평에서 주제 지식을 구성하거나 확인할 때는 [분야별 조사](references/domain-research.md)의 관련 부분만 적용한다. 역사·과학·생물은 [심화 관점](references/history-science.md)도 참고한다. 자료 조사가 필요 없는 최소 교정까지 확대하지 않는다.

유머·위트·능청·재치의 말투 조절, 제공된 문체 표본·참고 글의 전개 방식에 맞춘 새 글, 편집 의견의 선택적 반영, 다국어 글귀의 언어·문화 맥락 조절에는 [편집 방식](references/editorial-modes.md)의 해당 절만 적용한다.

AI 도구로 작업을 따라 하는 사용법·프롬프트·업무 활용 가이드는 사용 가능한 `ai-guide-writing`이 적합하다. 마케팅·PR 목적의 캠페인·광고·프로모션 이메일·SNS·보도자료·언론 대응 원고는 사용 가능한 `marketing-pr-writing`이 적합하다. 홈페이지·랜딩페이지의 소개·서비스·버튼·FAQ 문구는 사용 가능한 `website-copywriting`이 적합하다. CMS 관리자 화면의 버튼·저장·게시·권한·오류 문구는 사용 가능한 `cms-ux-writing`이 적합하다. 영상 시나리오·대본은 사용 가능한 `screenplay-writing`이 담당한다. 기술 주제라도 토론 게시글이면 커뮤니티 방식이 맞을 수 있다. 실행 가능한 구현·재현·기술 설명이 중심인 글은 사용 가능한 `tech-blog-writing` 스킬이 담당한다. 완성된 글의 번역·대조는 사용 가능한 `translate`가 담당한다. 해당 스킬이 없으면 전환을 했다고 주장하지 말고 요청 범위에서 직접 처리한다. 이 스킬의 글쓰기 작업에 다른 스킬을 필수로 요구하지 않는다.

## 공통 작성·퇴고 원칙

쓰기 전에 누가 누구에게 무엇 때문에 쓰는지 잡고, 그 화자가 고를 정보와 어휘를 중심으로 구성한다. 모든 장르를 친근한 대화체나 반듯한 해설문으로 통일하지 않는다. 자연스러운 말투·화자의 목소리·상투적인 전개를 다듬을 때는 [목소리와 문장 흐름](references/editorial-modes.md#자연스러운-목소리와-문장-흐름)의 기준을 적용한다.

- 설명·질문 글은 읽을 이유나 핵심 쟁점을 일찍 드러낸다. 일상 에세이·소설은 장면이나 목소리로 시작할 수 있고 결론·교훈·행동 지침을 의무적으로 붙이지 않는다. 제목은 본문이 전달하는 범위 안에서 쓴다.
- 구체적인 주어와 동사, 자연스러운 어순을 쓴다. 명사화·겹친 수식·상투적인 서두·같은 뜻의 마무리를 덜어낸다. 문장 길이와 문단은 흐름에 맞추고, 짧게 쓰려고 모든 문장을 끊거나 목록으로 바꾸지 않는다.
- 퇴고에서는 화자의 관점·감정의 강도·정중함·의도한 반복을 살린다. 압축 뒤에도 부정·조건·시간 순서·인과관계·불확실성을 원문과 대조한다. '자연스럽게'라는 요청만으로 주제나 결말을 바꾸지 않는다.
- 게시 장소의 규칙과 말투는 제공된 자료를 우선한다. 사이트명이나 언어만 보고 독자의 성향·지역·의견을 단정하지 않는다. 특정 저자의 문장을 복제하기보다 요청한 특징을 어휘·리듬·시점으로 구현한다.

## 검토와 전달

인물·관계·사생활을 다루거나 표현의 윤리성을 검토할 때는 [표현 윤리](references/expression-ethics.md)를 적용한다. 장면의 사실 여부와 별개로, 선택한 표현이 관계를 왜곡하거나 불필요한 함의를 더하지 않는지 살핀다.

먼저 요청 범위·주요 사실 또는 설정·화자·분량을 확인하고, 글만 다시 읽어 흐름과 말투를 점검한다. 장르가 달라지면 좋은 글의 기준도 달라진다. 소설의 의도적 모호함이나 개인 글의 감정을 설명 부족으로 자동 판정하지 않는다.

검토는 AI를 우선한다. 별도 검토 요청이나 복잡한 초안에서 위임이 허용되고 별도 AI 세션이 사용 가능하면 [독립 검토](references/ai-review.md)를 적용한다. 사용할 수 없으면 자체 검토 범위만 밝히고 독립 검토라고 하지 않는다. 사람의 승인을 기본 완료 조건으로 삼지 않는다.

기본 출력은 요청한 글 자체다. 요청하지 않은 기획 과정·제목 후보·검토표·반복 요약을 덧붙이지 않는다. 사실에 영향을 주는 미확인 사항은 필요한 위치에 짧게 밝힌다. 저장 요청이나 저장소 관례가 있을 때 해당 경로에 저장하며, 글 작성 요청만으로 외부 게시·댓글 등록·메시지 전송을 수행하지 않는다.
